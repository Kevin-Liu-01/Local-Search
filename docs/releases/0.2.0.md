# local-search 0.2.0

Native crate: `local-search` 0.2.0. npm bridge: `@kevinliu01/localsearch` 0.2.0,
pinned to the same native version.

## Changes

- Choose existing Chrome with approval or a separate persistent browser profile.
- Reuse one approved existing-Chrome connection across commands on macOS/Linux.
- Disconnect without closing Chrome. Lost sessions fail without automatic reconnect.
- Distinguish approval timeout, rejection, busy session, and disconnected browser.
- Keep search caches scoped to the connected browser session.
- Offer bounded, advisory release checks at interactive setup, plus `update-check`.
- Include the illustrated agent guide and explicit browser authority boundaries.
- Update the transitive `chacha20` dependency from yanked 0.10.1 to 0.10.2.

## Upgrade

```sh
cargo install local-search --version 0.2.0 --locked --force
# Or, with Node.js 18+ and Rust/Cargo:
npm install -g @kevinliu01/localsearch@0.2.0
```

This release changes browser setup: first use requires an explicit choice.
An older existing-browser configuration requires `lsearch connect --existing`
and fresh Chrome approval once after upgrading. Chrome 144+ is required for
existing mode. On Windows, choose `lsearch connect --managed`.

## Verification

On September 25, 2026 (Pacific time), crates.io published 0.2.0. Its sparse
registry index reports `yanked: false`. A fresh exact-version registry install
into an isolated Cargo root passed all three binary alias version checks,
`connect`/`disconnect` help checks, and isolated-config smoke checks. First use
fails with `browser_not_configured`, empty stdout, and a nonzero status;
disconnect succeeds without accessing a user browser.

The fresh Cargo binary also launched an isolated headless managed Chrome,
read a synthetic localhost page as JSON, and closed that test browser through
graceful `cleanup --kill`. It used a separate config, profile, and port; the
user's existing browser and selection were not accessed.

- `cargo fmt --check`, all 73 Rust tests, and strict Clippy passed.
- `cargo publish --dry-run --locked --allow-dirty` passed after the dependency update.
- Website lint, typecheck, build, and exported-docs checks passed.
- npm package and publish dry runs passed. The registry reports 0.2.0 as `latest`
  and `config.nativeVersion` as 0.2.0. After propagation, a fresh npm install
  with lifecycle scripts enabled built the native crate successfully; all four
  aliases reported 0.2.0. Its isolated-config smoke test preserved the same
  fail-closed JSON behavior as Cargo.
- The regenerated documentation captures passed 320, 390, 768, and 1440px checks.
