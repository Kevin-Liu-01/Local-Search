# local-search 0.3.0

Native crate: `local-search` 0.3.0. npm bridge: `@kevinliu01/localsearch` 0.3.0,
pinned to the same native version.

## Changes

Agent boundaries: ways to keep an agent out of tabs and sites it should not touch.

- `lsearch profile list|create|use|remove` switches between named browser
  profiles. `everyday` is your existing Chrome, `agent` is the managed profile
  and `custom` is a remembered endpoint. `profile create <name>` adds a separate
  managed Chrome profile with its own data directory and port.
- `lsearch policy block|allow|remove|show|reset` keeps per-profile site rules.
  A blocklist always wins. An allowlist, when present, limits the agent to those
  sites; search engines still work. Rules match a domain and its subdomains,
  `*.domain` for subdomains only, or `domain/path`.
- `lsearch policy tabs own` limits a profile to the tabs lsearch opened plus tabs
  the user grants with `lsearch tabs grant <id>` (`tabs revoke` takes one back).
- Page commands check the attached tab's site before acting. `open`, `read`,
  `record`, `back` and `forward` check where the tab landed after redirects and
  leave a blocked page for `about:blank`. `request` checks the final URL, `map`
  skips blocked links, `search --with-content` returns blocked placeholders and
  `cookies` filters by domain.
- Errors name the site only, never its path or query, and tell the agent not to
  route around the block.

These are guardrails for a cooperating agent, not a sandbox. A separate profile
is the isolation boundary; see SECURITY.md.

## Behavior changes

The defaults are unchanged: every profile starts with no site rules and any-tab
access. Even with no rules:

- Browser and extension pages (`chrome://`, `chrome-extension://`, `devtools://`,
  `view-source:`, `javascript:`, and `about:` pages other than `about:blank` and
  `about:srcdoc`) are always off limits.
- `tabs list` leaves those tabs out and adds `hiddenTabs` (a count of hidden page
  tabs) and `profile`.
- `open --new-tab` opens a blank tab and then navigates it, so it waits for the
  page to load like a plain `open`.
- `map` adds `blockedPages`.

Profiles are stored in `profiles.json` and the agent's tab record in `tabs.json`,
next to `config.json`. Existing configurations need no migration.

## Upgrade

```sh
cargo install local-search --version 0.3.0 --locked --force
# Or, with Node.js 18+ and Rust/Cargo:
npm install -g @kevinliu01/localsearch@0.3.0
```

## Verification — October 14, 2026

- Formatting, all 108 Rust tests and strict Clippy passed. The new tests cover
  rule parsing and matching, allowlists, browser schemes, search engines, cookie
  domains, the profile and tab records, own-tab profiles with grant and revoke,
  blocked sites, per-profile policies and profile management.
- Headless Chrome smoke checks: a blocked site was refused; a redirect into a
  blocked site was caught after it landed and the tab was reset to `about:blank`;
  allowed pages opened normally; `chrome://settings` was refused; a fresh browser
  reported `hiddenTabs: 0`.
- Locked Cargo packaging built the packaged crate. All three native aliases
  reported 0.3.0.
- npm package dry run verified native-version alignment and six intended files.

The arm64 macOS executable built with Rust 1.98.1 measures **1,355,744 bytes
(1.36 MB)**, up from 1,272,432 bytes in 0.2.1 for the profile and policy code. The
npm dry-run archive measures **3.3 kB** before native installation. The
compressed crate measures **99,691 bytes (97.4 KiB)**.
